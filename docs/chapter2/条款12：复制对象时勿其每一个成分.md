.## 条款12：复制对象时勿复制其每一个成分

**Copy all parts of an object**

这个条款提示我们，在手动编写拷贝函数（即拷贝构造函数和拷贝赋值运算符）时，要确保复制了对象内的所有成员变量以及基类成分。下面是两个文章提到的常见陷阱：

陷阱 1：忘记复制局部成员变量
```cpp
class Customer {
public:
    // ...
    Customer(const Customer& rhs) {
        name = rhs.name; // 只复制了 name
        LogCall("Customer copy constructor");
    }
    Customer& operator=(const Customer& rhs) {
        name = rhs.name; // 只复制了 name
        LogCall("Customer copy assignment operator");
        return *this;
    }
private:
    std::string name;
    Date lastTransaction; // <--- 新增的成员
};
```

- 问题： 假设这个类一开始只有 `name`，写好了拷贝函数。但后来新增了一个成员 `lastTransaction`。
- 后果： 编译器不会提醒更新 `Customer(const Customer&)` 和 `operator=`。手动写的代码仍然只复制 `name`。
- 结果： 新增的 `lastTransaction` 成员在拷贝时被遗漏了，导致拷贝出来的对象是一个不完整的局部拷贝，这几乎肯定是一个 bug.

陷阱 2：忘记复制基类部分
```cpp
// 派生类 (Derived Class)
class PriorityCustomer : public Customer {
public:
    // ...
    PriorityCustomer(const PriorityCustomer& rhs) { // <-- 错误的版本
        priority = rhs.priority;
        LogCall("PriorityCustomer copy constructor");
    }
    PriorityCustomer& operator=(const PriorityCustomer& rhs) { // <-- 错误的版本
        priority = rhs.priority;
        LogCall("PriorityCustomer copy assignment operator");
        return *this;
    }
private:
    int priority;
};
```
- 问题： `PriorityCustomer` 对象内部其实有两部分：`Customer` 部分（包含 `name` 和 `lastTransaction`）和 `PriorityCustomer` 部分（包含 `priority`）。
- 后果 (构造函数)： 在错误版本的拷贝构造函数中，我们忘记在成员初始化列表中调用基类的拷贝构造函数。C++ 会因此转而调用 `Customer` 的默认构造函数。导致 `priority` 被正确复制了，但基类的 `name` 和 `lastTransaction` 成员是默认初始化的，而不是从 `rhs` 复制过来的！
- 后果 (赋值运算符)： 在错误版本的拷贝赋值运算符中，我们忘记调用基类的拷贝赋值运算符。导致 `priority` 被正确赋值了，但基类的 `name` 和 `lastTransaction` 成员保持原样。

正确的方式应该是：
```cpp
// 在成员初始化列表中显式调用基类的拷贝构造函数：
PriorityCustomer::PriorityCustomer(const PriorityCustomer& rhs)
    : Customer(rhs),              // <-- 【解法】调用基类的拷贝构造函数
      priority(rhs.priority)      // <-- 复制自己的局部成员
{
    LogCall("PriorityCustomer copy constructor");
}

// 在函数体内显式调用基类的拷贝赋值运算符：
PriorityCustomer& PriorityCustomer::operator=(const PriorityCustomer& rhs) {
    LogCall("PriorityCustomer copy assignment operator");

    Customer::operator=(rhs);    // <-- 【解法】调用基类的拷贝赋值
    priority = rhs.priority;     // <-- 复制自己的局部成员
    
    return *this;                // (别忘了条款 10)
}
```
> 调用基类的 `operator=` 时，必须使用 `Customer::operator=` 这样的全名。如果只写 `operator=(rhs)`，它会被解析为递归调用 `PriorityCustomer::operator=`，导致无穷递归。

拷贝构造和拷贝赋值都需要复制局部成员。如果局部成员很多，代码会重复。条款指出，以下想法是非常不合理的：
- 拷贝赋值运算符调用拷贝构造函数
- 拷贝构造函数调用拷贝赋值运算符

条款而是建议提炼一个 `private` 辅助函数来处理。
```cpp
class PriorityCustomer : public Customer {
private:
    int priority;
    // ... 其他成员
    
    // 建立一个 private 辅助函数来复制所有局部成员
    void copyLocalMembers(const PriorityCustomer& rhs) {
        priority = rhs.priority;
        // ... 复制其他成员
    }

public:
    PriorityCustomer(const PriorityCustomer& rhs)
        : Customer(rhs)  // 1. 构造函数：在初始化列表处理基类
    {
        copyLocalMembers(rhs); // 2. 调用辅助函数处理局部成员
    }

    PriorityCustomer& operator=(const PriorityCustomer& rhs) {
        Customer::operator=(rhs); // 1. 赋值：在函数体处理基类
        copyLocalMembers(rhs);    // 2. 调用辅助函数处理局部成员
        return *this;
    }
};
```

上面这个私有辅助函数方案是可行的，但在 C++ 实践中，有一个更现代、更健壮、更异常安全的著名技巧，称为 "Copy-and-Swap" (拷贝并交换) 惯用法。
