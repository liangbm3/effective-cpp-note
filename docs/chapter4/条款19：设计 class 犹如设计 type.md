## 条款19：设计 class 犹如设计 type

**Treat class design as type design**

这是 C++ 面向对象设计中非常重要的一个条款，提醒我们当在 C++ 中定义一个 `class` 时，不仅仅在组合数据和函数，而是在创造一个全新的类型。这个新类型应该像 C++ 内置的 `int` 或标准库的 `std::string` 一样，表现得自然、符合直觉且功能完备。

在这个条款中，作者给了一个灵魂拷问清单，我们在兴奋地写下 `class MyClass { ... }` 之前，必须能够回答以下所有问题。

1. **新 `type` 的对象应该如何被创建和销毁？**这直接决定了构造函数和析构函数的设计，以及内存分配和释放函数的设计（是否需要重载 `operator new`, `operator delete`, `operator new[]`, `operator delete[]`）
2. **对象的初始化和对象的赋值该有什么样的差别？**这个答案决定构造函数和赋值运算符的行为以及它们之间的差异。
3. **新 `type` 的对象如果被 pass-by-value (以值传递)，意味着什么？**这直接决定了拷贝构造函数该如何实现。
4. **什么是新 `type` 的“合法值”？**一个类通常有其约束条件。例如，一个 `Date` 类的“月”成员变量的值必须在 1-12 之间。所有成员函数（特别是构造函数、赋值运算符和 "setter" 函数）都必须维护这些约束。如果约束被破坏（例如，用户试图设置 13 月），类应该如何反应？
5. **你的新 `type` 需要配合某个继承体系吗？**如果继承自基类，就必须遵守基类的设计（例如，virtual 和 non-virtual 函数的规定）。最重要的是：析构函数是否需要是 virtual？
6. **你的新 `type` 需要什么样的转换？**允许隐式转换吗？如果提供了一个“单参数构造函数”，例如 `MyClass(int x)`，就等于允许了从 `int` 到 `MyClass` 的隐式转换。如果提供了“类型转换运算符”，例如 `operator double()`，就等于允许了从 `MyClass` 到 `double` 的隐式转换。
7. **什么样的操作符和函数对此新 `type` 而言是合理的？**需要决定哪些函数应该是 `public`、`protected` 还是 `private`。哪些应该是 `member` 函数，哪些应该是 `non-member` 函数？哪些应该是友元函数？
8. **什么样的标准函数应该被驳回？**如果不希望类被拷贝，应该显式地将拷贝构造函数和拷贝赋值运算符声明为 `private` 或使用 `= delete`。
9. **什么是新 `type` 的“未声明接口” ？**这不是指函数签名，而是指类做出的“承诺”，包括：效率：这个操作是 $O(1)$ 还是 $O(n)$？异常安全性：这个函数提供什么级别的异常保证？资源运用：这个类是线程安全的吗？
10. **你的新 `type` 有多么一般化？**是在定义一个 `class`，还是在定义一个 `types` 家族？如果这个设计（例如一个 List）可以适用于多种其他类型（`List<int>, List<string>`），那么应该设计的不是一个 `class`，而是一个 `class template`。
11. **你真的需要一个新 `type` 吗？**如果只是为了给既有的 `class` 增加机能，也许定义一两个非成员函数或模板，是比创建一个新的 `derived class` 更好的选择。
